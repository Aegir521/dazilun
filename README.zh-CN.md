# 搭子论

[English](README.md) · **简体中文**

搭子论是一张由两个人共同记录的关系星图。一起打球、看电影、吃夜宵，每一种搭子身份都会在星图上成为一个词。共同投入的时间越多，词就越醒目。鼠标停在星环上，附近的星尘会持续起伏；快速划过时，星雾会留下逐渐消散的尾迹。

在星图或活动页打开 **显示设置 → 界面语言**，可以切换简体中文和英文。浏览器会记住你的选择，搭子姓名和自定义身份沿用录入时的文字。

## 从第一次绑定到第一条记录

1. 两位使用者分别登录同一个实例，在「我的搭子」里找到对方。一人发出绑定申请，另一人接受。
2. 在「记录活动」里自定义身份，例如「饭搭子」，也可以为它添加「周五夜宵」这样的细分。
3. 任选一方记录日期和时长。记在细分里的活动会自动汇总到主身份，只计一次。双方可以选择让新增活动经对方确认后计入。
4. 回到「关系星图」查看变化。词的大小依据有效活动的总时长乘以个人系数计算；系数默认 1，可在 0.1 到 5 之间调整。活动次数单独统计。还没有活动时，首页提供示例星图。

## 在本机运行

准备 Node.js 22.13 或更高版本及 npm，在项目根目录执行以下命令。第一条会从模板生成当前实例的配置，适用于首次运行。

```sh
node -e "require('node:fs').copyFileSync('.openai/hosting.example.json','.openai/hosting.json',require('node:fs').constants.COPYFILE_EXCL)"
npm run install:ci
npm run build
npm run db:init:local
npm start
```

打开终端打印的本地地址即可预览。数据库初始化命令用于空数据库。再次启动只需执行 `npm start`，本地记录保存在 `.wrangler/state/`。修改前端时可运行 `npm run dev` 进入开发预览。构建后的本地 Worker 可以查看示例星图；真实的双账号绑定需要部署到有登录服务的实例上。

## 在你自己的 GPT Sites 部署

需要一个可以创建 GPT Sites 站点的账号，以及能从本地源码发布的 Sites 开发环境。

1. 在自己的账号下新建一个站点，取得平台分配的项目 ID。
2. 将 `.openai/hosting.example.json` 复制为 `.openai/hosting.json`，在配置中加入自己的 `project_id`。保留 `"d1": "DB"`，让平台为这个实例提供独立的 D1 数据库。配置文件的完整示例如下。

   ```json
   {
     "project_id": "<你的站点项目 ID>",
     "d1": "DB",
     "r2": null
   }
   ```

3. 在支持 Sites 的 Codex 环境中打开项目目录并要求：“把当前目录发布到配置中指定的 GPT 站点，绑定该站点自己的 D1 数据库，并应用 drizzle 目录中的迁移。” 部署时应将这个实例的实际配置纳入该站点专用的源码版本。公开仓库的忽略规则会把它排除，使用单独部署检出时可在该检出中显式暂存配置。
4. 在站点共享设置中为使用者添加查看者访问权限。两人分别用自己的账号打开站点，接受绑定后，录入一条活动并刷新，核对星图和统计。

每个部署使用自己的登录、访问名单和数据库。以后更新代码时沿用同一个项目 ID 和数据库绑定，即可继续读取原有记录。迁移脚本只包含表结构。当前服务端依赖 GPT Sites 验证过的身份请求头，在其他平台部署时，需要接入该平台的身份验证并提供兼容的数据库绑定。

## 源码导航

| 路径 | 内容 |
| --- | --- |
| `app/cloud.tsx` | 星环绘制、悬停律动和词云布局 |
| `app/page.tsx` | 主页、搭子绑定与活动录入界面 |
| `app/model.ts` | 身份、活动审核、时长汇总与权重 |
| `app/api/orbit/route.ts` | 登录后的成员与关系数据接口 |
| `drizzle/` | 数据库迁移 |
| `.openai/hosting.example.json` | 自部署配置模板 |
